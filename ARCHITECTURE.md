# Architecture — BookWise: Multi-Tenant Accounting & Bookkeeping SaaS

This document describes the architecture of **BookWise**, a multi-tenant
Accounting & Bookkeeping platform for Sri Lankan SMBs, built on Laravel 12
(nwidart/modules) + Next.js 16.

## 1. Design decisions

| Decision | Choice |
| --- | --- |
| Multi-tenancy model | **Row-level tenant scoping** on a shared database, enforced by a global Eloquent scope keyed on `host_id`. |
| Existing non-accounting modules | **Repurposed**: CRM clients → customers/vendors, invoices → accounts receivable; unrelated modules left intact for later cleanup. |
| Scope | **Full double-entry core**: Chart of Accounts, Journal Entries, General Ledger, Bank/Cash, Bills (AP), Expenses, Reconciliation, and the four core financial statements, all tenant-scoped, with invoices wired to the ledger. |

## 2. Tenant model

The tenant is an **organization (SMB)** represented by the `hosts` row.
Every accounting table carries a `host_id` column and applies a global scope so
that a request can only ever read/write its own organisation's data.

- `App\Services\TenantManager` — resolves/stores the active tenant for the
  request lifetime. Super-admins may impersonate a tenant via the `X-Host-Id`
  header.
- `App\Http\Middleware\ResolveTenant` — registered in the `auth.verified`
  middleware group in `bootstrap/app.php`; sets the tenant from the
  authenticated user.
- `App\Traits\TenantScoped` — applied to every tenant-aware model. It:
  1. adds a global scope `where host_id = TenantManager::id()`;
  2. auto-stamps `host_id` on create;
  3. hard-requires `host_id` outside the console.
- `App\Traits\OwnerTrait` stamps `created_by` / `updated_by`.

## 3. Module map

| Module | Purpose | Key entities |
| --- | --- | --- |
| `Accounting` | Double-entry core | `accounts` (Chart of Accounts), `journal_entries`, `journal_entry_lines`, `fiscal_years`, `accounting_settings` |
| `Banking` | Bank/cash + reconciliation | `bank_accounts`, `bank_transactions` |
| `Purchases` | Accounts payable | `vendors`, `bills`, `bill_items`, `bill_payments` |
| `Expenses` | Overheads | `expense_categories`, `expenses` |
| `Invoice` (adapted) | AR | `invoices` link to `journal_entries` via `journal_entry_id` |

All modules follow the repository + service + form-request + resource + API
controller pattern.

## 4. Double-entry mechanics

A **journal entry** (`journal_entries` + `journal_entry_lines`) is the atomic
unit of the ledger. Each entry has ≥ 2 lines; every line is either a debit or
a credit against a Chart of Accounts node.

- `Modules\Accounting\Services\JournalService` owns the lifecycle:
  `draft → posted → (reversed)`.
- Posting is the **only** moment account balances change. It is guarded by a
  balanced check (`Σ debit == Σ credit`); an unbalanced entry cannot post.
- `Modules\Accounting\Services\AccountBalanceService` maintains each account's
  running balance.

## 5. Financial statements

All computed on-the-fly from posted journal entries:

| Statement | Endpoint |
| --- | --- |
| Trial Balance | `GET /api/v1/admin/accounting/reports/trial-balance` |
| Profit & Loss | `GET /api/v1/admin/accounting/reports/profit-loss` |
| Balance Sheet | `GET /api/v1/admin/accounting/reports/balance-sheet` |
| Cash Flow | `GET /api/v1/admin/accounting/reports/cash-flow` |

## 7. Localization

BookWise is localized for Sri Lanka:
- **Currency**: LKR (Rs.) — Sri Lankan Rupee
- **Timezone**: Asia/Colombo (UTC+5:30)
- **Date format**: DD/MM/YYYY
- **Locale**: en_LK

## 8. Environment configuration

See `.env.example` in both `be/` and `fe/` directories.

### Required variables

**Backend:**
- `APP_KEY` — generated by `php artisan key:generate`
- `DB_*` — database connection
- `PASSPORT_PRIVATE_KEY` / `PASSPORT_PUBLIC_KEY` — generated by `php artisan passport:keys`

**Frontend:**
- `NEXT_PUBLIC_API_BASE_URL` — backend API URL
- `NEXTAUTH_SECRET` — NextAuth.js secret

### Optional variables

- `STRIPE_*` — payment processing
- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — OAuth
- `NEXT_PUBLIC_GOOGLE_ADS_ID` — analytics
